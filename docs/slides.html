🎙️ Dica de Apresentação: Introdução rápida do grupo e objetivo: demonstrar uma arquitetura de referência na nuvem que não expõe nenhum componente interno à internet.

01. O Cenário e o Desafio

Requisitos centrais da migração e riscos mitigados

Emanuel

🏢 A Aplicação da Empresa

  • Interface Web: Frontend acessível por clientes na internet.
  • API de Negócio: Processamento de regras e requisições.
  • Banco de Dados: Armazenamento de dados transacionais sensíveis.
  • Upload de Arquivos: Envio e recuperação de anexos por usuários.

🎯 O Que Não Pode Acontecer

  • Risco Componentes internos (banco/API) expostos diretamente na internet.
  • Risco Ataques de injeção (SQLi), ataques volumétricos ou exfiltração de dados.
  • Risco Portas administrativas (SSH/RDP) abertas ou credenciais fixas no código.
  • Solução Defesa em Profundidade: Nenhuma camada confia cegamente na outra.
🎙️ Fala do Emanuel: "A empresa precisava migrar uma aplicação completa sem expor seu backend. O nosso foco foi desenhar uma infraestrutura resiliente, onde a quebra de uma camada não comprometa o restante do sistema."

02. Visão Geral da Arquitetura

Isolamento perimetral e segregação lógica de ambientes

Emanuel

🌐 1. Borda Pública Única

Os clientes nunca chegam diretamente aos servidores da empresa. Toda requisição obrigatoriamente passa por Route 53, CloudFront e WAF.

🛡️ 2. VPC em 3 Camadas

Divisão rigorosa entre Sub-redes Públicas (ALB), Privadas de Aplicação (ECS Fargate) e Privadas de Dados (RDS PostgreSQL).

🔒 3. Serviços PaaS / Serverless

Armazenamento em S3 isolado por VPC Endpoint, gerenciamento de segredos no Secrets Manager e observabilidade com CloudTrail + GuardDuty.

🎙️ Fala do Emanuel: "Construímos o ambiente em torno de uma VPC dedicada replicada em duas Zonas de Disponibilidade. O único componente que recebe tráfego de fora da nuvem é o CloudFront na borda."

03. Borda & Proteção Web

Garantindo HTTPS, mitigação de ameaças e integridade da origem

Vitor

🛡️ Componentes de Borda

  • Amazon Route 53: DNS autoritativo apontando exclusivamente para o CloudFront via registro Alias.
  • AWS CloudFront (CDN): Terminação TLS 1.2+ na borda com certificado gerenciado pelo ACM e cache de conteúdo estático.
  • AWS WAF: Bloqueio preventivo contra ataques comuns (OWASP Top 10, SQLi, XSS) e limitação de taxa (Rate Limit).

🔐 Mecanismo Anti-Bypass do ALB

Como garantir que ninguém tente acessar o ALB diretamente pelo IP ou DNS público dele?

  • Prefix List O Security Group do ALB só aceita conexões vindas da faixa oficial do CloudFront.
  • Custom Header O CloudFront injeta um cabeçalho HTTP secreto. O ALB valida esse cabeçalho e descarta requisições diretas.
🎙️ Fala do Vitor: "Explicar como o WAF limpa o tráfego sujo antes de entrar na AWS e como o cabeçalho secreto impede que qualquer atacante contorne a proteção do CloudFront."

04. Rede (VPC) & 3 Camadas de Sub-redes

Alta disponibilidade com 2 AZs e isolamento por tabelas de rotas

Vitor

1. Sub-redes Públicas

Componentes: ALB e NAT Gateways.
CIDR: 10.0.1.0/24 e 10.0.2.0/24

Única camada com rota direta para o Internet Gateway (0.0.0.0/0 → IGW).

2. Privadas (Aplicação)

Componentes: ECS Fargate, VPC Endpoints.
CIDR: 10.0.11.0/24 e 10.0.12.0/24

Sem IP público. Saída para internet exclusivamente para atualizações via NAT Gateway (somente saída).

3. Privadas (Dados)

Componentes: RDS PostgreSQL (Multi-AZ).
CIDR: 10.0.21.0/24 e 10.0.22.0/24

Zero rota para internet: sem NAT, sem IGW. Acesso restrito exclusivamente à sub-rede da aplicação.

🎙️ Fala do Vitor: "Destacar a segregação física/lógica: mesmo que a camada web sofra um incidente, não há caminho de rede direto da sub-rede pública até a sub-rede de banco de dados."

05. Processamento & Armazenamento Seguro

Arquitetura sem servidores operacionais e tráfego privado de dados

Pedro

⚙️ ECS Fargate (API & Web)

  • Zero SO para gerenciar: Elimina manutenção de Linux/Windows e portas SSH.
  • Tarefas sob demanda que escalam automaticamente conforme a carga.
  • Acesso restrito via IAM Task Role.

🗄️ RDS PostgreSQL Multi-AZ

  • Instância primária + réplica standby síncrona na AZ-B para failover automático.
  • Criptografia de disco em repouso com AWS KMS.
  • Conexões exigem TLS criptografado (porta 5432).

📁 S3 & VPC Gateway Endpoint

  • Arquivos dos usuários ficam em Bucket privado com Block Public Access ativado.
  • O tráfego da API para o S3 trafega pela rede interna da AWS via VPC Gateway Endpoint.
  • Bucket policy nega requisições fora do endpoint.
🎙️ Fala do Pedro: "O Fargate reduz dramaticamente a superfície de ataque ao eliminar servidores. E com o VPC Endpoint, os uploads para o S3 nunca transitam pela internet pública."

06. Fluxos de Comunicação & Firewalls

Encadeamento de Security Groups e bloqueios explícitos

Pedro

🔗 Encadeamento de Security Groups

As regras referenciam IDs de outros Security Groups, nunca faixas de IP voláteis:

  • sg-alb: Aceita 443 apenas do CloudFront → Envia 8080 para sg-app.
  • sg-app: Aceita 8080 apenas de sg-alb e sg-vpn → Envia 5432 para sg-db.
  • sg-db: Aceita 5432 apenas de sg-app e sg-vpn.

🚫 Conexões Bloqueadas Explicitamente

  • Bloqueado Qualquer tráfego direto da internet para o RDS ou ECS Fargate.
  • Bloqueado Conexões entre sub-rede pública e banco de dados.
  • Bloqueado Portas SSH (22) e RDP (3389) negadas tanto em SGs quanto em NACLs.
  • Bloqueado Acesso anônimo ou público ao bucket S3.
🎙️ Fala do Pedro: "Mostrar como o encadeamento de Security Groups garante o menor privilégio no nível de pacotes de rede. Se um contêiner for escalado com outro IP, as regras continuam válidas."

07. Acesso Administrativo Sem Bastion

Túnel seguro ponta a ponta com autenticação federada e MFA

Ricardo

❌ Por que NÃO usar Bastion Host?

  • Bastion exige manter uma instância EC2 pública com SSH aberto (porta 22).
  • Risco constante de ataques de força bruta e vulnerabilidades em pacotes de SO.
  • Gerenciamento complexo de chaves privadas (.pem) que podem ser compartilhadas ou vazadas.

✅ Solução Adotada: AWS Client VPN

  • Autenticação Federada: Integração com IAM Identity Center exigindo MFA obrigatório.
  • Autorização Granular: Apenas membros do grupo Administradores têm rota liberada.
  • Criptografia TLS: Tráfego administrativo totalmente criptografado.
  • Logs de Auditoria: Registro de quem conectou, quando e qual IP utilizou enviados ao CloudWatch.
🎙️ Fala do Ricardo: "Eliminamos completamente o conceito de Bastion Host e portas SSH abertas. O administrador só alcança o banco ou os diagnósticos da API após autenticar com MFA na VPN."

08. Menor Privilégio & Observabilidade

Gestão de credenciais dinâmicas e monitoramento contínuo de ameaças

Ricardo

🔑 Menor Privilégio & Segredos

  • AWS Secrets Manager: Senhas do RDS com rotação automática. O código da API nunca contém credenciais em texto claro.
  • IAM Roles Temporárias: Fargate utiliza Task Role para falar com S3 e Secrets Manager sem chaves fixas (Access Keys).
  • RBAC no IAM Identity Center: Permissões baseadas em funções com expiração automática de sessão.

👁️ Auditoria & Detecção de Ameaças

  • AWS CloudTrail: Rastreia 100% das chamadas de API (quem, quando, onde).
  • VPC Flow Logs: Telemetria de tráfego aceito e rejeitado.
  • Amazon GuardDuty: IA para identificar comportamentos anômalos e tentativas de ataque.
  • S3 com Object Lock: Logs armazenados de forma imutável (WORM).
🎙️ Fala do Ricardo: "Concluir destacando que segurança não é só firewall, mas rastreabilidade: qualquer alteração de configuração ou anomalia é detectada imediatamente pelo GuardDuty e pelo CloudTrail."
